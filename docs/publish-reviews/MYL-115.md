### ⚠️ 前提 3 的驗法本身有一個坑，記在這裡

`templates/publish-review.md:39` 建議的驗法是
`… | grep -o '\[[^]]*\]([^)]*)'`，**這條指令在本機環境恆回空、與內容無關**：
本機的 `grep` 是 `ugrep 7.5.0`，該 pattern 連純 ASCII 的 `+see [a](b.md) here` 都比不中
（已用最小重現確認：換 `-E`、換 `LC_ALL=C`、換純 ASCII 輸入，三種都仍是 0 命中；
而 `grep -E '\]\('` 與 python `re` 在同一份輸入上都正常命中 7 次）。

**它已經在一份永久記錄裡產生過假綠**：`docs/publish-reviews/MYL-73.md` 憑這條指令回空，
斷言 `06-org-structure.md` 那次「新增內容一條連結都沒加」；實測該次 diff
（`185dc19..0a0b4612`）新增了 **3 條**連結，其中 **2 條正是指向
`../../skills/foundry-protocol/SKILL.md` 的私有路徑**——也就是前提 3 存在的理由本身。
**那次的投影結果未必錯**（`rewrite_repo_links` 有測試蓋著，且本次實測改寫正常），
壞掉的是**證據**，不是產出。

改用可靠的驗法有兩條：`grep -E '\]\('`（MYL-102 記錄用的就是這條，會動），
或直接跑投影看輸出（本次採用，證據強度更高）。模板本身的修正不夾帶進本單，
已回報 Product Manager 另開單。
