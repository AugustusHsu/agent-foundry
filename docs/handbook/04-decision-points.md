# 4. 我要在哪幾個點做決定？

> 最後對照 protocol `6d28021`（2026-09-05）

> 本章自 MYL-9（跨平台流程）起改用「3 關卡」視角描述：你要做的決定收斂為三個抽象關卡＋一種觸發式追問。規則本體在 [`foundry-protocol` 第 4 節](../../skills/foundry-protocol/SKILL.md)。

你被問的方式只有兩種，都出現在 Paperclip 收件匣：

- **問答卡（ask_user_questions）**：單選／多選＋自由輸入，用在「有多個選項要你挑」。
- **確認卡（request_confirmation）**：核可／退回二擇一，用在「東西做好了，要你點頭才往下走」。

共通規則：**卡未回覆前，agent 只能做不受該問題影響的其他工作，不得先斬後奏**（protocol 第 4 節）。所以「不回卡」的後果永遠一樣——該條流程停在原地。

## 三個關卡

一次功能開發，常規流程只在三個關卡停下來等你：

| 關卡 | 回答的問題 | 什麼時候 | 預設核可者 | 可否調整 |
| --- | --- | --- | --- | --- |
| **A 規格核可** | 做什麼？ | 需求階段：選題、取捨、定稿 | 你 | 可（見下方「想調整被問的頻率」） |
| **B 方案核可** | 怎麼做？ | 設計階段：HLD 定稿交接時 | 你 | 可；小型工單可設定跳過 |
| **C 對外／不可逆核可** | 要不要出去？ | 收尾階段：push main、發佈、平台動作 | 你 | **不可調降，寫死** |

關卡之間的中段執行（排程、實作、code review、測試、本地 commit、文檔同步、agent 間交接）依決策權矩陣（[第 6 章](06-org-structure.md)）由各角色自動跑，你只收各階段的摘要留言。

## 關卡 × 決策點對照表

Pilot 時期你被問過 7 種決策點（本章舊版逐一記載）。它們與三關卡的對應如下：

| 關卡 | 對應決策點 | Pilot 卡片實例 |
| --- | --- | --- |
| **A 規格核可** | 1 選題 ＋ 2 需求取捨 ＋ 3 需求定稿 | `ask:MYL-6:pilot-topic:v1`、`ask:MYL-16:lint-requirements:v1`、`confirmation:MYL-16:prd-final:ac0c180` |
| **B 方案核可** | 4 階段交接（HLD 核可部分） | `confirmation:MYL-16:handoff-techlead:ac0c180`、`confirmation:MYL-17:handoff-sm:76f3089` |
| **C 對外／不可逆核可** | 5 實作交付（push／發佈部分）＋ 7 平台動作 | `confirmation:MYL-19:delivery:1451c4f`、`confirmation:MYL-6:skill-reimport:<commit>` |
| （不屬關卡） | 6 觸發式閘門——**原樣保留**，遇到才問，不受關卡設定影響 | 見下方 |

兩點說明：

- 決策點 5 的「驗收實作結果」併入關卡 C 前的摘要報告：你在核可對外動作時一併驗收，不再單獨發卡。
- 決策點 7（平台動作，例如公司層 skill 重新匯入）仍然只有你能做——平台不變式規定 agent 呼叫一律 403 `skill_actor_restricted`；它歸入關卡 C，**你不執行，依賴它的工單就一直等**（agent 被規範禁止空轉重試）。

## 各關卡你會看到什麼

### 關卡 A：規格核可（做什麼）

- 流程起點的**選題問答卡**（日常使用你直接丟題目就跳過）、需求階段的**取捨問答卡**（一次 3–5 題行為邊界），與收尾的**定稿確認卡**（附 BRD／PRD 與 commit）。
- 核可定稿＝這份文件成為後續所有階段的最高依據（文檔權威階序：設計文件 > 工單 AC > 對話）；退回＝Product Analyst 依你的理由改完再送一輪。**不答，需求單停在原地**——protocol 禁止 agent 用「合理假設」代替你的答案。

### 關卡 B：方案核可（怎麼做）

- 設計交接的**確認卡**，附交接包（HLD／LLD 路徑＋已確認決策清單）。
- 核可＝設計與其 ADR 技術選型定稿、上一單結案、下一棒開工；退回＝Tech Lead 補齊再送。

### 關卡 C：對外／不可逆核可（要不要出去）

- 出現在任何**離開私有環境或覆水難收**的動作前：push main／force-push／tag、新開公開資源、擴大公開同步範圍、公司層 skill 匯入等平台動作。
- 卡片附交付摘要（AC 對應／風險警告／驗證建議），你核可對外動作時一併驗收成果。
- **這一關不可調降**：任何設定檔、任何 agent 都不能替你按下這個鈕。你也可以透過這一關給予**常設授權**（例：MYL-23 核可後，例行推送與手冊主閱讀面同步改為自動執行）——給予、擴大、收回常設授權本身永遠回到關卡 C。
- **手冊「發一版」也在這一關**：精裝站是打 `handbook-v<N>` tag 才發的，而 tag 發佈屬你專屬、沒有常設授權。agent 會把審查記錄準備好、發卡請你打 tag；tag 一推，CI 就把那一版建上站，站上同時留住 `v1`、`v2`…與 `latest`。⚠️ **推之前要先解一道鎖**：repo 上有一條 `handbook-version-tags` 規則擋住 `handbook-v*` 的建立，而它擋的是**所有人、包含你自己**（這個 repo 裡你和所有 agent 共用同一個 GitHub 身分，規則分不出誰是誰）。路徑是 Settings → Rules → Rulesets → `handbook-version-tags` → 切 Disabled，推完 tag 再切回 Active；忘了切會看到 `GH013 … creations being restricted`。這條規則買到的不是「只有你能打 tag」，是**擋掉誤推**（`git push --tags` 順手把本地 tag 掃上去）**和留下痕跡**（要違規得先關掉一個看得見的開關）。**已經發出去的版本號不重打**——要修就發下一版，CI 會擋下重打（見[第 7 章](07-workflows.md)第 6 節）。日常的手冊修訂**不會**走到這一關——那條路只更新主閱讀面（wiki），是 P2。

## 觸發式閘門（不定時，遇到才問）

以下六種情況任一出現，執行中的 agent 會立刻停手、發卡問你、把工單轉 `blocked`（protocol 第 4 節 HITL 閘門）。**這條通道不受關卡粒度設定影響**——就算你把 A、B 都調成自動，這些情況照樣會問你：

| ID | 觸發 | 你會被問什麼 | 不同選擇的後果 |
| --- | --- | --- | --- |
| `H1` | 未決事項未解 | 這個開放問題你要選哪個答案 | 你的答案寫回文件後才開工；不答就不開工。 |
| `H2` | 規格矛盾（文件、AC、對話打架） | 兩邊說法並列，你裁定聽誰的 | 裁定後由負責角色先改文件再繼續；agent 無權自行判定「照理說誰對」。 |
| `H3` | 要花錢 | 這筆費用（金額不論大小）花不花 | 同意才執行；沒有「反正很便宜」的豁免。 |
| `H4` | 要對外發佈 | 這個離開私有環境的動作（開 public repo、發佈、對外訊息）做不做 | 同意才執行；已在常設授權範圍內的動作（如 MYL-23 的 P1／P2）不再逐次問。 |
| `H5` | 破壞性操作 | 刪資料、覆寫成果、改 git 歷史、動生產環境，做不做 | 同意才執行；且執行前要先在隔離環境驗證機制。 |
| `H6` | 平台權限之外的動作 | **請你去做**某件 agent 做不到的事（組織與公司層設定變更等） | 這種卡不是要你選 A 或 B，是要你動手；agent 會停下等你完成回覆，不會空轉重試。 |

> **那些 `H1`、`H2` 是什麼？** 規範裡每條可判定的規則都有一個**穩定編號**。
> 章節號會隨規範增修而變動，編號不會——所以工單留言和審查報告會寫「觸發 `H3`」
> 而不是「第 4 節第 3 點」。你在卡片或留言看到這種編號時，它指的就是這張表裡的那一條。

另有一條鐵律讓你被問的頻率高於直覺：文件或對話裡的「建議用 X」「預設可以是 Y」都是**待確認選項，不是決定**——agent 會發卡列出選項與代價等你選定，不會因為「建議看起來很合理」就直接採用。

## 想調整被問的頻率？

- 關卡設定存在各專案的 `.foundry/config.yml`（schema 見 [`skills/foundry-platform/config-schema.md`](../../skills/foundry-platform/config-schema.md)）：A、B 兩關可改核可者，B 關可設小型工單跳過。
- 調整一律走 `foundry-gates` workflow：agent 盤點現況、給建議，**由你確認後才寫入**——agent 不能自行調整自己被管的粒度。
- **關卡 C 沒有調整路徑**：`gates.external_actions` 只允許 `user`，設定檔出現其他值會被整檔拒用。

## 一句話總結

一次功能開發，你的必答題就是三關：**A 規格（做什麼）→ B 方案（怎麼做）→ C 對外（要不要出去）**；其餘都是遇到錢、對外、破壞性、矛盾、平台權限時的觸發式追問。收件匣清空，流程就不會因你而停。
