## 1. 概述

foundry-lint 是一個小 CLI，給 Foundry 各角色 agent 在交棒前使用：讀取 `docs/` 下的交接文件，對照 `templates/` 對應模板的必備章節，判定文件結構齊不齊、缺了哪些章節，解決 BRD 第 1 節「交接物齊備只能肉眼比對」的問題。

## 2. 功能需求

### FR-1：單一文件的必備章節檢查

- **描述**：當使用者對一份文件執行 foundry-lint 時，系統應比對該文件類型對應模板的必備章節；全部存在則判定通過，缺任一章節則判定不通過並逐一列出缺少的章節名。
- **驗收條件**：
  1. 以 `templates/prd.md` 骨架完整撰寫的文件執行檢查，結果為通過。
  2. 將上述文件移除任一必備章節（如「## 5. 邊界情況與錯誤處理」）後執行檢查，結果為不通過，且輸出中包含該缺少章節的名稱。
  3. 缺多個章節時，全部缺少的章節都被列出，不是只報第一個。
- **優先序**：必須有（題目定義本身，MYL-6 互動卡已確認）

> FR-2 之後的功能需求（涵蓋的文件類型範圍、嚴格度分級、文件類型指定方式、輸出格式）依第 6 節未決事項的互動卡結果補寫；未確認前不預寫，避免未確認需求混入正文。

## 3. 非功能需求

尚無已與使用者確認的非功能需求；候選維度（如執行時間、離線可用）待需求確認後由互動卡或後續確認補入，不預設。

## 4. 流程與介面

已確認的主流程（介面細節待第 6 節確認後補齊）：

1. 使用者在終端執行 foundry-lint 並指定要檢查的文件。
2. 系統讀取文件、判定其文件類型對應的模板，取得必備章節清單。
3. 系統逐章節比對，輸出過／不過判定；不通過時列出缺少的章節。

指令形式、文件類型的指定／判別方式、輸出格式（含是否提供機器可讀格式）均為未決，見第 6 節。

## 5. 邊界情況與錯誤處理

| 情境 | 預期行為 |
| --- | --- |
| 指定的檔案不存在或無法讀取 | 判定為執行錯誤（非「檢查不通過」），並明確告知是哪個路徑讀不到 |
| （其餘邊界情境——空文件、無法判別文件類型、非 Markdown 檔案等——的預期行為隨第 6 節介面決策確認後補入） | — |

## 6. 未決事項

以下待使用者透過互動卡 `ask:MYL-16:lint-requirements:v1` 回答；全部清空前本文件不得交棒：

- 要檢查哪些文件類型：六份模板全上，或先做子集？（影響 FR 清單與第 5 節）
- 檢查規則的嚴格度／分級：只有「缺章節＝不通過」一級，還是 error／warning 分級（例如引導文字未刪除列 warning）？（影響 FR 清單與輸出設計）
- CLI 使用介面：文件類型自動判別、參數明確指定、或混合（預設自動＋可覆寫）？（影響第 4、5 節）
- 輸出形式：人類可讀文字＋exit code 即可，還是另需 JSON 等機器可讀輸出？（影響第 4 節與 FR 驗收條件）
- 各 FR 的最終優先序：待上述範圍確認後，連同驗收條件於 PRD 定稿確認卡一併與使用者確認。
