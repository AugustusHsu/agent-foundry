## 1. 概述

foundry-lint 是一個小 CLI，給 Foundry 各角色 agent 在交棒前使用：讀取 `docs/` 下的交接文件，對照 `templates/` 對應模板的必備章節，判定文件結構齊不齊、缺了哪些章節，解決 BRD 第 1 節「交接物齊備只能肉眼比對」的問題。

需求層四個決策點已由使用者於互動卡 `ask:MYL-16:lint-requirements:v1`（2026-09-03）選定：**六份模板全上、單級嚴格度（缺章節＝不通過）、`--type` 明確指定、文字＋exit code 並加 `--format json`**。以下正文均以此為準。

## 2. 功能需求

### FR-1：單一文件的必備章節檢查

- **描述**：當使用者對一份文件執行 foundry-lint 時，系統應比對該文件類型對應模板的必備章節；全部存在則判定通過，缺任一章節則判定不通過並逐一列出缺少的章節名。嚴格度為單級：只判定章節存在與否，不設 warning 層級，也不判斷章節內容品質。
- **驗收條件**：
  1. 以對應模板骨架完整撰寫的文件執行檢查，結果為通過。
  2. 將上述文件移除任一必備章節（如 PRD 的「## 5. 邊界情況與錯誤處理」）後執行檢查，結果為不通過，且輸出中包含該缺少章節的名稱。
  3. 缺多個章節時，全部缺少的章節都被列出，不是只報第一個。
  4. 文件含模板以外的額外章節、或必備章節存在但內容留空時，不影響判定（仍為通過）——只檢查必備章節存在性。
- **優先序**：P0（必須有）

### FR-2：六種文件類型全數支援

- **描述**：檢查規則涵蓋 `templates/` 下全部六份模板：brd、prd、hld、lld、review-report、test-plan。各類型的必備章節清單以對應模板檔為唯一權威來源。
- **驗收條件**：
  1. 六種類型各取一份依模板完整撰寫的文件，逐一執行檢查，全部回報通過。
  2. 六種類型各取一份缺任一必備章節的文件，逐一執行檢查，全部回報不通過並列出缺漏章節。
- **優先序**：P0（必須有）

### FR-3：以 `--type` 明確指定文件類型

- **描述**：使用者以 `foundry-lint --type <類型> <檔案路徑>` 執行，`<類型>` 為 brd／prd／hld／lld／review-report／test-plan 六值之一；一次指令檢查一份文件。不做自動判別。
- **驗收條件**：
  1. `foundry-lint --type prd docs/features/foundry-lint/PRD.md` 形式的指令可正確執行檢查。
  2. 未提供 `--type` 或提供的值不在六種合法值內時，回報使用方式錯誤（含合法值清單），不進行檢查，且 exit code 與「檢查不通過」可區分（見 FR-4）。
- **優先序**：P0（必須有）

### FR-4：人類可讀文字輸出＋exit code

- **描述**：預設輸出為人類可讀文字：通過時明示通過；不通過時列出每個缺少的章節名。exit code 分三類：`0`＝檢查通過、`1`＝檢查不通過、`2`＝執行／使用錯誤（檔案讀不到、參數錯誤等）。
- **驗收條件**：
  1. 通過、不通過、執行錯誤三種情境的 exit code 分別為 0、1、2（可由 shell 腳本判斷驗證）。
  2. 不通過時，文字輸出逐行（或逐項）列出缺少的章節名，肉眼可直接對照模板。
- **優先序**：P0（必須有）

### FR-5：`--format json` 機器可讀輸出

- **描述**：加上 `--format json` 時，改以 JSON 輸出檢查結果，至少包含：受檢檔案路徑、文件類型、過／不過判定、缺少章節名清單。exit code 行為與文字模式完全一致。JSON 欄位命名與詳細結構由 HLD 定案。
- **驗收條件**：
  1. `--format json` 下輸出為可被標準 JSON parser 解析的合法 JSON，且含上述四項資訊。
  2. 同一份文件在文字模式與 JSON 模式下的過／不過判定與 exit code 一致。
- **優先序**：P1（應該有）——已確認納入本版範圍，實作順序排在 P0 之後。

## 3. 非功能需求

- **NFR-1（離線可執行）**：檢查過程不呼叫任何網路服務；在含 `templates/` 的 repo 內單機即可執行（承 BRD 第 5 節限制）。驗收：斷網環境下執行 FR-1 驗收情境，行為不變。

## 4. 流程與介面

主流程：

1. 使用者在終端執行 `foundry-lint --type <類型> <檔案路徑>`（可另加 `--format json`）。
2. 系統依 `--type` 取得對應模板的必備章節清單，讀取受檢文件。
3. 系統逐章節比對存在性，依 `--format` 輸出判定結果；不通過時列出缺少的章節，並以 exit code 0／1／2 回報通過／不通過／執行錯誤。

介面規格摘要（技術實作與 JSON 詳細結構由 Tech Lead 於 HLD 定案）：

| 項目 | 規格 |
| --- | --- |
| 指令形式 | `foundry-lint --type <類型> [--format json] <檔案路徑>` |
| `--type` 合法值 | brd／prd／hld／lld／review-report／test-plan |
| 檢查單位 | 一次指令檢查一份文件 |
| 預設輸出 | 人類可讀文字 |
| `--format json` | 機器可讀 JSON（含檔案路徑、類型、判定、缺漏章節清單） |
| exit code | 0＝通過；1＝不通過；2＝執行／使用錯誤 |

## 5. 邊界情況與錯誤處理

| 情境 | 預期行為 |
| --- | --- |
| 指定的檔案不存在或無法讀取 | 執行錯誤（exit 2，非「檢查不通過」），訊息明確指出是哪個路徑讀不到 |
| 未提供 `--type`，或值不在六種合法值內 | 使用方式錯誤（exit 2），訊息列出合法值清單，不進行檢查 |
| 受檢文件為空檔案 | 視同缺少全部必備章節：檢查不通過（exit 1），列出全部必備章節 |
| 文件含模板以外的額外章節 | 不影響判定；只檢查必備章節是否存在 |
| 必備章節存在但內容為空 | 判定通過；內容品質不在本工具範圍（BRD 第 4.2 節） |
| `--format json` 模式下發生執行錯誤 | exit code 與訊息語意跟文字模式一致；錯誤輸出格式細節由 HLD 定案 |
